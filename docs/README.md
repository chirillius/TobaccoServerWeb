# TobaccoServer: запуск и совместимость сервисов

## Исправление от 2026-10-06

В этой версии нет миграций TobaccoServer. Раньше `Database.Migrate()` не создавал основную схему, после чего создание `ConversionRegisterEvents` падало с SQL Server 1767: отсутствовала `dbo.DefectImages`.

Теперь `AppDbContext` вызывает `DatabaseSchemaInitializer`:

- Если базы нет, создаёт её. SQL-пользователю для этого нужны права создания базы; можно заранее создать пустую базу в SSMS.
- Если нет пользовательских таблиц либо есть только `dbo.__EFMigrationsHistory`/`dbo.__EFMigrationsLock`, создаёт все таблицы текущей модели EF, затем добавляет таблицу событий.
- Если основная схема уже существует, сохраняет её и добавляет только отсутствующую `ConversionRegisterEvents`.
- Если обнаружена неполная или посторонняя схема, останавливается с перечнем недостающих таблиц. Не удаляет и не пересоздаёт существующие таблицы.
- Создание таблиц выполняется в одной транзакции с `sp_getapplock`, чтобы параллельные контексты не создавали таблицы одновременно.

Подключение задаётся переменной `ConnectionStrings__Default` или строкой `Default` в `App.config` (при сборке переносится в `TobacoServer.dll.config`). Не передавайте значения с паролями в логи или отчёты. У пользователя SQL должны быть права создания таблиц, индексов и ограничений в выбранной базе.

Это инициализация схемы версии без миграций, а не автоматическое исправление любых расхождений колонок. Для будущих изменений модели нужны версионированные миграции и согласование с существующей схемой. Нельзя просто добавлять начальную миграцию поверх рабочей базы: она попытается повторно создать таблицы.

## Сборка и запуск на Windows

### Получение исходников из GitHub

Из общего каталога сервисов:

```powershell
git clone https://github.com/Kvantron-L/TobaccoEntities.git TobaccoEntities
git clone https://github.com/chirillius/TobaccoServerWeb.git TobaccoServer
git clone https://github.com/chirillius/CentralServerWeb.git CentralServerWeb
```

Для закрытых репозиториев нужен аккаунт с доступом. Neuro обновляется отдельно: репозиторий для него в этой публикации не задан. Изменения контракта и фиксации фотографий требуют обновления его исходников вместе с остальными сервисами.

В каталоге `TobaccoServer` перед сборкой создайте локальные конфигурации:

```powershell
Copy-Item .\TobaccoServer\App.config.example .\TobaccoServer\App.config
Copy-Item .\TobaccoServer\appsettings.example.json .\TobaccoServer\appsettings.json
```

Заполните адреса микросервисов и SQL-подключение для площадки. Задайте одинаковый `Security__InternalApiKey` у CentralServer и TobaccoServer либо заполните локальное `Security:InternalApiKey`. Для нового экземпляра создайте каталог `Configuration` рядом с запускаемым EXE и скопируйте туда содержимое `TobaccoServer/Configuration.examples`. Шаблон отключает все задания аналитики; включайте их после настройки камер, зон, моделей и адресов сервисов. На существующей площадке сохраните её конфигурации.

`ffmpeg.exe` не хранится в Git. Для видео и аудио разместите свою Windows x64 сборку FFmpeg в `TobaccoServer/ffmpeg.exe` до публикации, чтобы проект скопировал её в выходной каталог. Крупные модели, фотографии, видео, логи, `bin/obj`, пароли камер и настройки площадки исключены из Git; конфигурационные шаблоны содержат только исходную схему без секретов.

Сохраните соседнее расположение каталогов `TobaccoServer` и `TobaccoEntities`. После обновления структуры пользователем `ProjectReference` указывает на `..\..\TobaccoEntities\TobaccoEntities\TobaccoEntities.csproj` относительно файла сервера. Если ваша Windows-копия устроена иначе, измените эту ссылку на фактический путь. В `.sln` пути тоже обновлены. Версии OpenCV сервера согласованы с Entities; фиксированный RID убран из библиотеки сущностей, при этом Windows-зависимости OpenCV сохранены.

У Neuro, TobaccoServer и CentralServer используется ссылка на проект `..\..\TobaccoEntities\TobaccoEntities\TobaccoEntities.csproj`. При сборке каждого сервиса библиотека собирается автоматически; это исключает старую DLL с контрактом без многоугольников. Путь в solution CentralServer также обновлён.

Из каталога, содержащего `TobacoServer.sln`:

```powershell
dotnet build .\TobacoServer.sln -c Debug --source https://api.nuget.org/v3/index.json
cd .\TobaccoServer\bin\Debug\net8.0
.\Start.bat
```

Исправление применяется только после переноса изменённых исходников и пересборки на Windows. Старый EXE/DLL в `bin\Debug` продолжит выполнять прежний код. Базу с одной историей EF вручную удалять не требуется.

## Проверка

Проверки SQL startup, приведённые ниже, относятся к предыдущему исправлению. Пользователь затем обновил исходники и удалил `TobaccoServer.Tests`; этот набор сейчас отсутствует. Доступные проверки геометрии и контрактов описаны в разделе «Многоугольные зоны».

Проверено на Mac: Release-сборка решения, Debug-сборка сервера для `win-x64` и 10 регрессионных сценариев. Используются реальная модель, SQL Server-провайдер EF и его `CreateTables`, но соединение записывает команды вместо обращения к SQL Server. Проверены порядок таблиц/внешних ключей, новая и пустая базы, история EF без таблиц, добавление событий к старой схеме, повторный запуск, неполная/посторонняя схема, откат при ошибке DDL и отказ при недоступной блокировке. Это не проверка исполнения T-SQL, прав пользователя или реальных данных на Windows.

На Windows после пересборки нужно подтвердить запуск с выбранной базой и повторный запуск с сохранением данных. Перед проверкой рабочей базы сделайте резервную копию. Камеры, ONNX и нативный OpenCV в рамках этого исправления не проверялись.

## Многоугольные зоны — 2026-10-06

Совместимый контракт Zone расширен полями `polygon: [{x,y}, …]`, `referenceWidth`, `referenceHeight`. Координаты относятся к полному исходному превью; клиент сохраняет размер 1920×1080. Rectangle содержит охватывающий прямоугольник и вычисляется сервером из вершин. Без polygon остаётся прежняя прямоугольная обработка; отсутствие размеров превью означает прежние координаты в пикселях. Зоны хранятся в существующем `Configuration/zones.json`, изменение SQL-схемы не требуется.

CentralServer передаёт контур и все параметры конверсии в TobaccoServer. Сохранение JSON выполняется с заменой файла и обновлением кеша зон под блокировкой; работающие задания видят новый контур или удаление без перезапуска. Изменение контура сбрасывает трекинг конверсии, даже если охватывающий прямоугольник прежний.

Neuro обрезает охватывающий прямоугольник и маскирует внешние пиксели контура для анализа объектов/классификации. Детекции объектов проверяются по центру bbox; принадлежность человека клиентской/сервисной зоне — по нижнему центру bbox. Подсчёт людей и конверсии для многоугольников использует детекции полного кадра, чтобы маска напольной зоны не скрывала торс человека. Прямоугольники сохраняют прежний способ подсчёта. Движение ограничено маской; освещение использует число пикселей внутри контура; сравнение чистоты маскирует одинаковый контур в эталоне и текущем кадре и исключает внешние пиксели из расчёта.

Фото сохраняется полным кадром, без чёрной маски. EXIF UserComment содержит объект Zone с контуром, массив Bboxes относительно начала Rectangle и Result для логических результатов. Исправлены строка вместо объекта Zone, повторная JSON-сериализация и координаты бейджа/отрицательного результата дыма после второго crop. UUID в имени исключает совпадение файлов при одновременных результатах; разбор времени и перенос снимков поддерживают одновременно прежние имена и новый суффикс. В коллажах телефона/бутылки/дыма и чистоты прилавка контур наносится на снимок перед компоновкой. Просмотрщик клиента также умеет отображать многоугольный overlay чистоты прилавка. Его дополнительная разметка строится по текущим настройкам зон; контур на самом новом фото остаётся зафиксированным на момент съёмки.

### Обновление Windows

Сохраните соседнее расположение `TobaccoEntities`, `TobaccoServer`, `Neuro`, `CentralServerWeb`. Обновите все эти исходники и пересоберите сервисы; обновите frontend из `webArchiveRetrievalOriginal`. Старая версия CentralServer или Neuro может проигнорировать polygon и обработать весь охватывающий прямоугольник. Существующие модели, конфигурацию площадки, эталон чистого прилавка, SQL-данные и фотографии сохраните при замене пакетов.

Из корня `webArchiveRetrievalServers` выполняйте сборки последовательно, поскольку они используют одну библиотеку:

`tests/ZoneContract.Tests` — локальный межсервисный набор проверок в общей папке сервисов. Он не входит в четыре отдельных репозитория этой публикации и требует актуальных исходников Neuro. Команды сборки сервисов доступны после клонирования; команды тестового набора ниже предназначены для полного локального дерева.

```powershell
dotnet build .\TobaccoServer\TobaccoServer\TobacoServer.csproj -c Release -r win-x64 --source https://api.nuget.org/v3/index.json
dotnet build .\Neuro\Neuro\Neuro.csproj -c Release -r win-x64 --source https://api.nuget.org/v3/index.json
dotnet build .\CentralServerWeb\CentralServer\CentralServer.csproj -c Release -r win-x64 --source https://api.nuget.org/v3/index.json
dotnet restore .\tests\ZoneContract.Tests\ZoneContract.Tests.csproj --source https://api.nuget.org/v3/index.json
dotnet run --project .\tests\ZoneContract.Tests\ZoneContract.Tests.csproj -c Release --no-restore
```

### Проверка и границы

На Mac прошли 39 backend-проверок геометрии, DTO client → CentralServer → TobaccoServer → Neuro, сохранения/обновления кеша, направленного трекинга и полного JPEG с EXIF. Дополнительно проверена генерация DDL модели CentralServer реальным SQL Server-провайдером EF без подключения к базе. На клиенте прошли 19 проверок геометрии/коллажа; production build успешен. В изолированном браузере проверены создание вогнутого контура, редактирование, старые прямоугольники, пересечения сторон, замыкание первой точкой/Enter, стрелки, zoom/pan и конверсия; desktop 1600 px и mobile 390 px без горизонтального переполнения. Release и Windows x64 сборки трёх сервисов успешны с существующими предупреждениями. У редактора сохраняются старые lint-ошибки (сверены с исходной версией); новый модуль геометрии проходит ESLint.

Пять OpenCV-проверок автоматически выполняются тестовым проектом на Windows: маска вогнутой зоны без изменения полного кадра, число допустимых пикселей, освещение белой зоны, совпадение эталона чистоты и контур вместо bbox. На Mac они явно пропущены. Выполнение камер, ONNX/CUDA, реального SQL и Quartz-фиксаций на площадке здесь не подтверждено; качество классификаторов на кадрах с маской требует проверки на ваших моделях.

Перед вводом в работу подтвердите на Windows: человек внутри и снаружи вогнутого контура; каждый используемый тип нарушения; переход полосы в обоих направлениях; полный кадр/контур/bbox в сохранённом фото и коллаже; появление события в SQL и клиенте; отсутствие изменений вне зоны при оценке освещения/чистоты. Сравните с тем же сценарием на старой прямоугольной зоне.
